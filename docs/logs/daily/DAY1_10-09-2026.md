## Key decisions

- **`numpy<2` pinned.** Python is 3.11.16, so current versions were taken for
  everything else; numpy is pinned because `neurokit2==0.2.7` predates the ABI
  break. A consequence of the neurokit2 pin, not of the Python version.
- **Grad-CAM hand-rolled**, not the `grad-cam` package — ~40 lines of hooks, and
  inlining it keeps the script runnable inside a Kaggle kernel.
- **`04_segment_qc` writes a new directory** instead of repairing `03`'s output
  in place. The first version mutated its own dependency, which DVC cannot track
  and which destroyed the evidence of what had been repaired.
- **Augmentation seeds per (segment, variant)**, extending the brief's
  per-segment example, so adding or reordering variants cannot silently change
  existing values.
- **`method="fft"` and PIL's antialiased resize** in the scalogram stage. The
  first is 4.2× faster and numerically identical; the second is a *correctness*
  fix — `scipy.ndimage.zoom` point-samples and loses 3.1% of the field's mean at
  a 27× time-axis reduction.
- **Reflect-pad before the CWT** (see Blockers).
- **Training goes to Kaggle.** Measured ~500 s/epoch on CPU vs ~27 s/epoch on a
  T4. Local 5-fold CV across all families would be ~120 h; it does not finish.
- **`scripts/remote/05_run_queue.py` added** beyond the brief's 01–04, because
  Kaggle caps batch GPU sessions at 2 and ~60 jobs turn "push, poll, fetch" into
  a scheduler. It also keeps the quota ledger §9 requires.

## Blockers

**The CWT boundary artifact — resolved, at the cost of discarded work.**

Rendering the first paper figure showed the ECG scalogram was almost entirely
dark: two bright bands at the edges, near-black between. Outer columns carried
~19× the interior energy; interior mean 4.6/255; 85% of pixels below 26/255.
PCG was fine.

Cause: the CWT cone of influence at ECG scales up to 500, where the wavelet is
as long as the 6000-sample window. Fixed by reflect-padding by `4 × max(scale)`
and cropping back — interior mean 4.6 → 59.3, edge/interior 19.29 → 0.55.

Stopped the training queue, discarded 4 completed kernels and 3 scalogram
configs, and regenerated. **This was worth doing rather than noting**: Grad-CAM
would have highlighted the artifact and Contribution 2 would have reported a
false physiological conclusion.

Every numeric QC gate passed while this was wrong. It took looking at a picture.

**Resolution confirmed, both ways.** After regeneration: edge/interior
**19.29 → 0.80**, interior mean **4.6 → 60.5**. Visually, the ECG scalogram now
shows three low-frequency energy concentrations — the cardiac cycles — with
high-frequency QRS transients beneath, aligned in time with the PCG's S1/S2
bursts. Physiologically coherent, and no edge bands.

`verify_pad.py` measures the edge/interior ratio for any config and is the check
to run on every scalogram set before it feeds training. It tests the artifact
itself rather than file timestamps, so it is immune to the bookkeeping confusion
below.

**A process failure worth recording: a stopped job that did not stop.**
`TaskStop` on the ablation generation killed its *Python child* but not the bash
`for` loop wrapping it. The loop simply moved to the next wavelet config and
kept going — spawning `w4`, then `w5`, competing for all 16 cores and roughly
doubling the default regeneration time, while writing configs whose provenance
(pre- or post-fix) was then ambiguous.

Two lessons. Kill the *loop*, not the current iteration — check with
`ps -ef | grep <script>` afterwards rather than trusting the stop. And when
provenance becomes ambiguous, do not reason from timestamps: measure the
property that actually matters. All ablation configs were discarded regardless.

## Results so far

First post-fix fold, `ecg_only` CV fold 0: **segment AUC 0.841, patient AUC
0.870**, 30 epochs before early stopping. The pre-fix run on a different fold
gave 0.792 / 0.798 in 8 epochs. Different folds, so indicative rather than
controlled — but the direction and the epoch count both match the mechanism:
with the boundary artifact gone the images carry real signal, so validation AUC
keeps improving for far longer.

**A quota-accounting bug, found by asking why a kernel took 35 minutes.** The
ledger recorded wall clock from push to terminal status, which includes Kaggle's
scheduling queue. True in-kernel runtime for that job was 7.9 min against 35.6
min of wall clock — over-counting GPU time by 4.5x. Kaggle's 30 h/week budget is
GPU session time, so this would have halted the run at roughly a fifth of the
real allowance and put a wrong compute figure in the paper. Fixed by reading the
true runtime from the returned kernel log, falling back to wall clock when the
log is missing. Worth noting the trigger: the number was not obviously wrong, it
was just surprising, and checking why paid off.

**Contribution 1 is confounded, and the table now says so.** Noticed while
watching the ablation generation log: config w5 reported a PCG band of
15.4-285.7 Hz where the default reported 12.5-232.1 Hz - same scales, different
band. Each wavelet has its own centre frequency, so fixing the scales fixes the
scales, not the Hz. Measured spread across the four ablated wavelets is 3.2x
(`cmor1.5-1.0` 4-100 Hz on ECG vs `mexh` 1-25 Hz).

The brief's instruction to hold scales fixed stands - retuning per wavelet is a
much larger experiment. But it means the comparison confounds wavelet shape with
frequency coverage, so `03_build_results_tables.py` now prints the measured band
per row and the caption states the limitation outright. Caught from a log line
that looked merely surprising.

**MLflow contamination from a short-circuited cleanup — caught by a number that
moved when it should not have.** `ecg_only` fold 2 read 0.8296 at one check and
0.7241 a few minutes later. A completed fold's metrics are immutable, so that
was impossible and worth chasing.

Cause: the cleanup before the rebuild was written as
`rm -rf <busy dir> && rm -rf models/ecg_only reports/ecg_only models/mlflow_tracking ...`.
The first `rm` failed because a stopped job still held the file, `&&`
short-circuited, and **nothing after it ran**. Six pre-fix MLflow runs survived
and sat alongside their post-fix replacements. Averaging would have produced a
"5-fold CV" mean over seven runs from two different versions of the data - a
number corresponding to no real experiment, and one that would have looked
entirely normal in the table.

Fixed: stale runs identified by start time against the moment the padded dataset
went live (10:45 UTC) and deleted; six removed, zero pre-cutoff remaining.
`03_build_results_tables.py` now hard-fails on duplicate (family, config, fold)
runs - the visible symptom of this class of contamination - and the guard is
tested.

Two lessons. Never chain cleanup with `&&`; use `;` or `|| true`, because a
cleanup step that fails silently leaves exactly the debris it was meant to
remove. And a metric that changes when it cannot change is worth stopping for.

**Fusion does not beat ECG alone, on a clean split.** With `ecg_only`,
`pcg_only` and `dual_cnn` all complete at 5-fold CV, the paired per-fold
comparison says: `pcg_only` -0.2117 patient AUC vs `ecg_only`, losing all five
folds (p = 0.001); `dual_cnn` -0.0136, losing four of five (p = 0.334).

Added `scripts/evaluation/05_paired_model_comparison.py` because mean +/- std is
the wrong instrument here - fold-to-fold spread is ~0.09 while the differences
of interest are ~0.01, so marginal means would hide both a real difference and
the absence of one. Every family sees identical folds, data and seed, so the
fold is a matched unit and the paired difference is the right statistic. With
k = 5 the tests have almost no power, and the script's own output says so: a
p above 0.05 means the experiment cannot distinguish the families, not that they
are the same.

Worth stating plainly because it contradicts the old pipeline, which reported
fusion 0.817 > ECG-only 0.795 - from a validation split that leaked at the
patient level.

**Building the Docker image found a bug that no test could.** The inference
image had been written but never built. On first run the container died at
startup, exit code 3: `load_model()` did `checkpoint["model"]` unconditionally,
which is right for a training checkpoint but wrong for the TorchScript export
the image actually ships - that deserialises to a RecursiveScriptModule and
subscripting it raises NotImplementedError. Every API test passed throughout,
because they point at the .pth.

It also exposed a real tension in the brief: §13 asks the inference image to
carry "only a TorchScript export" AND to serve /explain. Both cannot hold, since
Grad-CAM needs backward hooks that a scripted module's internals do not accept.
Resolved by shipping both artifacts (~5 MB each), defaulting to the eager one so
all three endpoints work, with /health reporting `supports_explain` and /explain
returning a 501 with an explanation rather than a stack trace.

Smoke-tested against the running container on real held-out data: /health ok,
/predict 6/6 correct, /explain a valid 240 KB PNG.

The lesson is the same one the CWT artifact taught: an artifact that has been
written but never *run* is untested, and the failure it hides is usually not the
one you would have guessed.

4. **`scripts/remote/05_run_queue.py` added** beyond the specified 01–04, for

5. **Reflect-padding added to the scalogram transform.** The brief specifies the
   wavelet, scales, `np.abs`, and the resize; it does not specify boundary
   handling. Padding is a fix to an artifact, not a change to the specified
   transform.
