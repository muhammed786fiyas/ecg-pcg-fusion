# Day 3 — 2026-09-12

## Work done

**Step 4 of the improvement list: pretrain the PCG branch on PhysioNet 2016
subsets B-F** (owner's choice, after the ResNet-18 baselines showed fusion adds
+0.008 over ECG alone). The PCG branch is the bottleneck - even pretrained on
ImageNet, PCG-only reaches 0.741 - and B-F hold ~2,800 heart-sound-only
recordings, about 7x Training-A.

The whole design was written and committed **before any B-F data was
processed or any model trained**, so it is a declared experiment, not one
shaped by its results:

- **Data** (`scripts/pretrain/`, three DVC stages). PhysioNet's `training.zip`,
  subsets B-F only. Each PCG gets Training-A's exact processing - per-record
  peak normalisation, the same record QC thresholds, the same segment QC, the
  same CWT transform (a test pins the two transform copies byte-equal).
  **Training-A is never read**, and a guard hard-fails on any Training-A
  record ID.
- **Windows.** 3 s like Training-A, but fixed and non-overlapping from the
  start of each record, not R-peak-centred - B-F have no ECG. Capped at 20 per
  record so a few long recordings cannot dominate. A stated limitation.
- **Split.** Record-level train/val (85/15), stratified by subset and label,
  for early stopping only; same contract as the Training-A split (sees record
  IDs, strata and a seed only; a test asserts the signature). No pretraining
  test set: no pretraining number is a result.
- **Pretraining** (`scripts/modeling/pcg_pretrain/`). `resnet18_pcg_only`'s
  model, 30 epochs max, patience 5, pos_weight from the B-F train manifest.
- **Fine-tuning.** `resnet18_pcg_only_pcgpre` and `cross_attn_resnet18_pcgpre`,
  generated from their un-pretrained twins; they differ only in initialising
  the PCG branch from the pretrained checkpoint (and hard-fail without it -
  no silent ImageNet fallback). Same hyperparameters, folds, seed.
- **Kaggle.** The pretraining run uses its own dataset; the fine-tuning jobs
  get the checkpoint as an extra dataset, found by the entry script.
- **Comparisons, fixed in advance:** `resnet18_pcg_only_pcgpre` vs
  `resnet18_pcg_only` (does pretraining help PCG?), and
  `cross_attn_resnet18_pcgpre` vs `resnet18_ecg_only` and vs
  `cross_attn_resnet18` (does fusion now add anything?). Paired per fold.

## Key decisions

- Keep B-F recordings of every signal quality, as Training-A kept all of its
  records; the record and segment QC gates are Training-A's.
- Subject overlap between Training-A and B-F: none expected - different
  databases collected at different sites. The challenge's validation set,
  which re-uses training records, is not used.
