## Key decisions

- **Keep the misclassified example.** Swapping in a normal record the model gets
  right would be choosing examples by outcome. Instead the demo now shows the
  ground truth next to the prediction for bundled examples, and names the model's
  usual error: calling normal records abnormal (patient-level specificity 0.77 vs
  sensitivity 0.93 in cross-validation).
- **One fold's weights, not a 5-fold ensemble** — simpler and faster on a free
  CPU Space. Discussed below.

**Lowering the decision threshold - done on validation, and it costs a lot of
specificity.** The owner asked why records are
scored by the MEAN of their window probabilities rather than "abnormal if any
window is abnormal". The any-window rule is the max strategy: on
`cross_attn_resnet18` it gives sensitivity 0.972 but specificity 0.513, because
25.6% of windows from normal records score above 0.5 and a record has ~9 of
them. To illustrate the alternative I showed that the mean with a threshold of
0.31 reaches the same 0.972 sensitivity at specificity 0.641 - but that 0.31 was
picked by looking at TEST results, which I flagged as illustration only.

The owner then asked for a lower threshold, so it was done properly:
`scripts/evaluation/06_screening_threshold.py` fits, per fold, the highest
threshold reaching a target record sensitivity on the INNER-VALIDATION records,
then applies it to that fold's test records. Validation predictions were
recomputed on CPU; recomputed test predictions matched the Kaggle GPU ones to
within 0.023. Record predictions are cached, so the target sweep is free.

| validation target | threshold (fold 0) | test sensitivity | test specificity |
|---|---|---|---|
| default 0.5 | 0.5 | 0.931 +/- 0.033 | 0.770 +/- 0.041 |
| 90% | 0.657 +/- 0.127 (0.598) | 0.903 +/- 0.032 | 0.829 +/- 0.076 |
| 95% | 0.428 +/- 0.147 (0.522) | 0.938 +/- 0.028 | 0.743 +/- 0.090 |
| 98% = 100% | 0.129 +/- 0.133 (0.378) | 0.983 +/- 0.022 | 0.486 +/- 0.200 |

The first attempt, a 95% target, did not lower the threshold at all: fold 0
came out at 0.522, above 0.5, for almost no sensitivity gain. 98% and 100% are
identical because ~35 abnormal validation records means 98% requires all of
them. Catching every one reaches 0.983 test sensitivity, but specificity halves
and the threshold is set by the single lowest-scoring abnormal validation
record, so it is unstable: 0.378, 0.084, 0.0001, 0.044, 0.137 across folds.
Fold 2's is effectively "call everything abnormal" (test specificity 0.13).
The 0.31 / 0.972 / 0.641 illustration was test-set optimism; the honest cost of
that sensitivity is specificity ~0.49.

**Deployed:** target 100%, so the demo uses fold 0's **0.378**. On fold 0's own
test fold that is sensitivity 0.966 / specificity 0.739 (0.931 / 0.826 at 0.5).
The demo and the Space README state both the fold-0 rates and the
cross-validated 0.983 / 0.486, and that the threshold is unstable. The paper's
headline numbers stay at 0.5; the sweep is the operating-point result.

**Reverted to 0.5 the same day - owner decision.** Put per 100 patients at this
dataset's 71% prevalence, the low threshold avoided ~4 missed abnormal records
at the cost of ~8 extra false alarms (balanced accuracy 0.85 -> 0.73). At a
realistic 10% screening prevalence it would mean ~256 extra false alarms per
1000 people to catch ~5 more patients. The fitted value is also set by a single
validation patient per fold. The demo is back at 0.5; the sweep stays in the
paper as the operating-point trade-off, and `screening_target_sensitivity` is
now analysis only.

**No public demo - owner decision.** The local demo (port 7860) is enough. The
HuggingFace upload path stays in `build_hf_space.py` but is not planned.

**Does fusing ECG and PCG actually help? Barely - measured directly.** The owner
asked. New `scripts/evaluation/07_modality_permutation.py`: within each fold's
test records, one modality is swapped for the same modality from a different
record (records deranged as a whole, 5 permutations per fold). Branch feature
maps are computed once and re-paired, so the backbone runs once per fold; the
intact condition reproduces the saved Kaggle predictions (max drift 0.027).

| model | intact | PCG swapped | ECG swapped |
|---|---|---|---|
| `cross_attn_resnet18` | 0.938 +/- 0.039 | 0.913 +/- 0.049 (-0.024, 4/5 folds) | 0.525 +/- 0.031 |
| `cross_attn_fusion` | 0.851 +/- 0.081 | 0.787 +/- 0.070 (-0.064, 5/5) | 0.545 +/- 0.050 |

The best model is almost entirely an ECG model. A second check: averaging the
`ecg_only` and `pcg_only` record probabilities (equal weights, nothing fitted)
gives 0.840 +/- 0.093 vs 0.864 for ECG alone, worse in 4/5 folds - the
custom-CNN PCG model is too weak to add anything. The gap in the evidence: no
ResNet-18 ECG-only model was ever trained, so the claim that the +0.074 comes
from the backbone and not the fusion is inferred. Proposed to the owner with
four improvement ideas (stronger backbones, training recipe, PCG pretraining on
PhysioNet 2016 subsets B-F, the gaus4 ECG wavelet), with the caution that any
run chosen after seeing CV results is a declared follow-up, not a new headline.

**ResNet-18 unimodal baselines - owner approved, run first.** Two new families,
`resnet18_ecg_only` and `resnet18_pcg_only`. Each script is derived from
`cross_attn_resnet18/01_train.py` by a transform that copies everything outside
the model section byte-for-byte; the diff is the header, `MODEL_FAMILY`, the
model section and one MLflow param (`modality`). So the baselines share the
fusion model's lr (1e-4), 50-epoch schedule, early stopping, pos_weight and
seed, and the branch is identical including the 256-d projection. The only
changes: one branch instead of two, no cross-attention, and a
`Linear(256, 128)` head instead of `Linear(512, 128)`. Registered in the Kaggle
sync, reconcile, the paired comparison and `tests/test_model.py` (which now also
checks that each baseline ignores the other modality). These are chosen after
seeing CV results, but they are baselines, not tuned models - selection bias
cannot flatter the fusion model through them. The Kaggle dataset got a new
version carrying the two scripts.
